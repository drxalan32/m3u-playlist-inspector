M3U Playlist Examples: Simple, Extended and Grouped Formats

Looking for an M3U playlist example you can understand and adapt? This guide shows the basic structure of a plain M3U list and common extended M3U entries, including display names, groups and optional channel metadata.

Every media location below uses the reserved example.com domain. These are format demonstrations only, not working streams, channel lists or IPTV access details. Replace a placeholder only with a media location you own or are authorized to use.

Privacy and authorization: Real playlist URLs may contain usernames, passwords or access tokens. Keep private playlist files and credentials out of screenshots, public repositories, forums and support posts. Only use media sources you are authorized to access.

1. Simple M3U playlist example

A basic M3U playlist can be a text file containing media locations, usually one per line. A minimal illustrative example is:

https://example.com/media/first-item.mp3
https://example.com/media/second-item.mp3

This simple form does not include extended entry descriptions. Applications differ in the playlist types and URL schemes they accept.

2. Extended M3U playlist example

An extended M3U playlist commonly starts with #EXTM3U. Each #EXTINF line describes the next item, and the media location follows on the next line.

#EXTM3U
#EXTINF:-1,Example Live Channel
https://example.com/live/example-channel.m3u8
  • #EXTM3U identifies the extended playlist header.
  • #EXTINF introduces information for the next entry.
  • -1 is commonly used for a live or unknown-length item.
  • The comma separates the metadata portion from the display name.
  • The next line contains the media location.

The example URL is a placeholder and is not expected to play.

3. M3U playlist example with groups

Some IPTV-oriented playlist formats use the optional group-title attribute to label entries for display in categories. The exact behavior depends on the player.

#EXTM3U
#EXTINF:-1 group-title="News",Example News
https://example.com/live/example-news.m3u8
#EXTINF:-1 group-title="Documentary",Example Documentary
https://example.com/live/example-documentary.m3u8
#EXTINF:-1 group-title="Sports",Example Sports
https://example.com/live/example-sports.m3u8

In this illustration, the group names are simply labels. They do not prove that an entry belongs to a real channel category or that the URL is available.

4. M3U example with TVG metadata

Some playlist applications recognize attributes such as tvg-id, tvg-name, tvg-logo and group-title. They are optional conventions, not universal requirements.

#EXTM3U
#EXTINF:-1 tvg-id="news.example" tvg-name="Example News" tvg-logo="https://example.com/images/news.png" group-title="News",Example News
https://example.com/live/example-news.m3u8
AttributeTypical purposeRequired?
tvg-idIdentifier some players use when matching programme guide data.No
tvg-nameAlternative or guide-facing channel name in some playlist ecosystems.No
tvg-logoReference to an image used as a channel logo.No
group-titleCategory label that some players display as a group.No

Attribute names and support can vary. Check the documentation for the player or playlist format you use rather than assuming every application interprets them in the same way.

5. M3U example with multiple entries

A playlist with several entries repeats the #EXTINF and media-location pattern. Keep each location directly after the metadata line it belongs to.

#EXTM3U
#EXTINF:-1 group-title="Demo",Example One
https://example.com/media/one.m3u8
#EXTINF:-1 group-title="Demo",Example Two
https://example.com/media/two.m3u8
#EXTINF:-1 group-title="Demo",Example Three
https://example.com/media/three.m3u8

For a deeper explanation of the header, tags and file extensions, read the M3U file format guide.

How to keep multiple entries correctly paired

Read an extended playlist from top to bottom. Each #EXTINF record describes the next media-location line. Keep the description and its location together, then begin the next entry with another #EXTINF.

#EXTM3U
#EXTINF:-1,First example
https://example.com/media/first.m3u8
#EXTINF:-1,Second example
https://example.com/media/second.m3u8

Do not insert an unrelated media URL between an #EXTINF line and the location it describes. That can make the entry pairing ambiguous or incorrect for a parser.

6. Common M3U formatting mistakes

  • Missing the #EXTM3U header in an extended playlist.
  • Leaving out the comma between #EXTINF metadata and the display name.
  • Adding another #EXTINF before the previous entry's media location.
  • Leaving an entry without a media location.
  • Using malformed quotation marks or line breaks inside metadata attributes.
  • Assuming optional metadata is supported identically by every player.
  • Publishing a playlist that contains private credentials or access tokens.

A text-format check can identify some structural problems, but it cannot confirm that media is online or that playback works.

Quick checklist before saving an M3U file

  • Use plain text and save the file with an .m3u or .m3u8 extension appropriate to the content and application.
  • For an extended playlist, include one #EXTM3U header at the beginning.
  • Place each #EXTINF line immediately before its matching media location.
  • Check that each metadata line contains the comma separating attributes from the display name.
  • Use consistent line breaks and properly paired quotation marks around attribute values.
  • Remove credentials from examples or screenshots before sharing a playlist.

These checks improve the file's structure, but compatibility still depends on the application and its supported playlist conventions.

Frequently asked questions

What does a basic M3U playlist look like?

A simple M3U file can contain media locations as text lines. An extended playlist commonly starts with #EXTM3U and uses #EXTINF records to describe entries.

What is the difference between simple M3U and extended M3U?

A simple list can contain media locations, while an extended playlist adds a header and metadata records such as #EXTINF. Player support and accepted attributes vary.

Are group-title and tvg-id required?

No. They are optional metadata conventions used by some playlist applications. Support and interpretation vary by player.

Should every M3U playlist start with #EXTM3U?

Extended M3U playlists commonly begin with #EXTM3U. A simple list of media locations may use a more minimal form. Follow the format expected by the application that will read the file.

Where should I put the media URL in an extended M3U file?

Place the media location on the line immediately after the #EXTINF record that describes it. Repeat this pair for each entry.

Do these example URLs play media?

No. The examples use example.com placeholder URLs to demonstrate syntax only. They are not working media sources.

Can the M3U Playlist Inspector test whether a stream works?

No. It checks supported playlist text structure locally and does not connect to media URLs or test playback.
